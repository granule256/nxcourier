# NxCourier 改动留痕流程

> ★ 本文是本项目的**开发流程约定**（随仓库一起发布）。
> 文里提到的 `docs/改动日志-平台.md`、`.workbuddy/memory/` 是维护者**本机的记录目录**，
> 不随仓库发布 —— 你要照着做的话，自己挑个位置记就行，重点在**记什么**，不在记在哪。
> 全文只读、不改设备；真正会动设备的是构建与部署那几步。

**这个项目的头号规矩是：任何改动都要留痕。** 起因是 2026-10-05 深夜排查
「主机熄屏后 `omm` 崩溃」时，**没有任何版本对照**，答不出"崩溃前后到底差在哪"，
三条嫌疑（轮询 / SD 挂载 / boot2 位置）全靠猜。

## 什么时候用

只要你要**改 NxCourier 里的任何东西**——设备侧 C++、PC 侧脚本、卡上文件、构建配置——
就走这个流程。**改完不写日志 = 没改。**

## 一 改之前

1. **想好回退路径**。★ 这条是血泪教训：我改动 socket 配置把平台搞挂过一次，
   而当时**没有回退方案**，只能求人开 FTP 手动恢复。
2. 如果动的是"地基"（网络栈、内存布局、加载方式）——**先问用户**。

## 二 构建

```bash
# ★ 必须在仓库根目录下跑：Makefile 要从根目录的 VERSION 取版本号，
#   所以挂载点也必须是根目录。只挂 device/platform 的话容器里看不到 VERSION，
#   构建会回落成带 `-unpinned` 后缀的版本号（一眼能看出没接上，不会悄悄报错版本）。
cd ~/code/github/NXC
docker run --rm -v "$PWD":/work -w /work/device/platform devkitpro/devkita64:latest \
  bash -lc '. /opt/devkitpro/devkita64.sh && make -j4 2>&1 | grep -vE "field not present" | tail -12'
```

★ 判据不是"零警告"：那串 `field not present` 是**无害噪音**（官方模板同样报）。
★ 看工具数：`aarch64-none-elf-objdump -h nxc.elf | grep nxc_tools`，
  段大小 ÷ **40**（`nxc::Tool` 结构体的大小）= 工具数。当前 `0x230` = 560 ÷ 40 = **14** 个。
  （★ 旧文档写的"÷ 32"是结构体还是 32 字节时的算法，**已经过期**，照它会算出 17.5。）
★ 顺带确认版本号接上了：`strings nxc.nso | grep -E '^[0-9]+\.[0-9]+\.[0-9]+$'` ——
  出现 `-unpinned` 就说明 `VERSION` 没读到。

## 三 留备份（改设备侧代码时必做）

```bash
cp nxc.nsp dist/exefs.nsp
cp nxc.nsp "dist/backup/exefs-$(date +%H%M)-<一句话说明>.nsp"
shasum -a 256 dist/exefs.nsp
```

## 四 部署（不需要 FTP）

```bash
cd ~/code/github/NXC && python3 -c "
import sys; sys.path.insert(0,'pc'); import nxc_mcp
d = nxc_mcp.Device('<设备IP>', 47800, 60.0)
print(nxc_mcp.tool_deploy(d, {'local_path':'device/platform/dist/exefs.nsp'}))
d.close()"
```

★ **必须看到 `verified: True`**（会读回比 sha256）。**校验不过就别重启。**
★ sysmodule 是开机加载的 ⇒ **部署完必须重启才生效**；重启后主机停在冷启动界面，
  **要人工按 3 次**才能进桌面，那期间所有端口拒绝。

## 五 验证

**没验证就在日志里写"未验证"。** 假装的验证比没有更坏。

常用手法：
```bash
python3 pc/nxc.py 'identify.id' 'tele.all'        # 基本读数
python3 pc/nxc_ctl.py act "DRIGHT:120"            # 按键 → 等画面变了
```
★ **旧路径还在时，用"新写法 vs 旧写法逐字节对答案"来验收**（最稳）。

## 六 ★ 写改动日志（在提交之前）

在 `docs/改动日志-平台.md` **顶部**加一条，照文件里给的表格：

| 项 | 内容 |
| --- | --- |
| **改了什么** | 具体到文件 + 函数/常量名 |
| **为什么** | 动机；修 bug 就写清原来错在哪 |
| **产物** | `dist/exefs.nsp` sha256 前 16 位 |
| **部署了吗** | **是（boot=N）** ／ **否**（只落在 dist/） |
| **验证** | 怎么验的 + 结果；没验就写"未验证" |
| **风险/回退** | 可能出什么问题、退回去用哪个文件 |

## 七 提交

```bash
cd ~/code/github/NXC
git ls-files --others --exclude-standard -z | xargs -0 git add --   # 逐路径，不用目录
git commit -F - <<'EOF'
<一句话标题>

改了什么 / 为什么 / 产物 sha / 部署了吗 / 验证结果 / 回退方式
EOF
```

★ **绝不 `git add <目录>/`** —— 逐路径列文件名。
★ 提交信息里**必须写清"部署了吗"**，否则说不清设备上跑的是哪一份。

## 排障方法论（2026-10-05 一晚硬仗换来的）

### ★★★ "完全禁用"是最强的归属实验

排查"是不是我们引起的"时，**先做这个，别急着列嫌疑清单**：

```
把 /atmosphere/contents/<TID>/flags/boot2.flag 改名成 .OFF  →  重启
   不崩 ⇒ 确定是我们      还崩 ⇒ 确定不是我们（彻底排除）
```
★ **只改名不删目录** —— `exefs.nsp` 留着，恢复只要把文件名改回来，不用重传 180KB。
★ 代价：禁用期间端口不会起来，**PC 侧完全失联**，恢复要走 FTP 或拔卡。

### ★★★ 读数必须在「正确的时刻」取

我测"`sm` 会话到底关了没"时，第一版取在**命令执行中**——
那时 `SmGuard` 开着，必然读到"开着"，**说明不了任何事**。
改到 `SmGuard` **打开之前**读（`sm_at_entry`）才有意义。

⇒ **问自己：这个读数取在什么时刻？那一刻的状态是我要测的状态吗？**

### ★★ 用户说"你确定吗"的时候 —— 去测，别解释

libnx 的 `sm` 是**引用计数**的（`serviceGuardExit` 里只有 refCount 归零才 `serviceClose`），
所以「我调了 `smExit`」**不等于**「会话真关了」。
★ 能查会话真实状态的函数：`serviceIsActive(smGetServiceSession())`。

### ★★ 用 `addr2line` 把崩溃偏移变成函数名

```
aarch64-none-elf-addr2line -e nxc.elf -f -C 0x<偏移>
```
★ 这一招把"主机进不去系统"直接定位到了 `fopen` 内部的 `_open_r`（空指针）。

### ★★ 重启后按 3 次的实测时序（AI 可以自己做，不用求人）

| 项 | 实测值 |
| --- | --- |
| 端口 `47800` 重新可连 | 重启后约 **35 秒** |
| ★ 启动画面**接受输入** | 约 **47 秒**（早于此时按 = 白按） |
| ★ 按住时长 | **必须 150ms**（90ms 不被接受） |
| 脚本 | 端口一通 **+12 秒**，再发 `A:150;WAIT:400;A:150;WAIT:400;A:150` |

★★ **必须【正好 3 下】** —— "多按一下保险"是错的：第 4 下会落在桌面图标上**把游戏启动**。

## 常见坑（改这个项目前先看）

| 坑 | 说明 |
| --- | --- |
| `tmp/` 有 184MB | 已 gitignore，**别手滑 `git add -A`** |
| `dist/` **故意入库** | 它是"设备在跑哪一份"的凭据 + 回退材料 |
| 中文引号混进代码 | `「」` 才对；混过三次，编译失败 |
| 改了容量常量要成对改 | 设备侧 `kArgValueBytes` ↔ PC 侧 `DEPLOY_CHUNK` ↔ 校验里的上限 |
| 自我更新要用保守分块 | 大分块旧设备收不下会**静默截断**，写坏自己的模块 |
| 批量按键只能用无分支环节 | 我连按 6 次 A，在存档选择上替用户做了选择 |
| FTP 传不了中文文件名 | 卡上文件名用 ASCII |
| ★★★ **`fsdevUnmountAll()` 之后 `fopen` 会崩**（libnx 的 `_open_r` 空指针），**不是返回 NULL** | 任何"按需挂载 SD"的设计，必须保证**每次文件访问前先 `sd::ensure()`**；否则是**崩溃**而不是可控失败 |
| ★★★ **boot2 模块的任何改动 = "可能开不了机"** | 改完**先在纸上推演整条开机路径**；重启前想好拔卡恢复方案 |
| ★★ **改"状态位 / 资源生命周期"必须全局搜所有读取点** | 我三次栽在"改了写的地方、漏了读的地方"（`kInitSd` 那次直接让主机进不去系统） |
| ★★★ **"某符号已清除"的断言，别去查裸名字** | 我**四次**栽在这：把要删的代码写进"解释为什么删"的注释里，于是 `assert "X" not in t` 炸了（或更糟：静默通过）。★ **查"调用形式"**（带括号/分号/类型后缀，且新注释里不会出现的那个写法），或用正则锚定行首 |
| ★★★ **replace 必须配断言** | 我写过一条 `t.replace(marker, ...)` 没断言 —— 而那个 marker 早被别的改动删掉了，**什么都没替换，脚本还是打印了 OK**，害我多编译一轮 |
| **拔卡恢复** | 卡插 Mac → 把 `exefs.nsp` 换成 `dist/backup/` 里已知可用的那份 → 逐字节校验 → `sync` 再弹出 |
